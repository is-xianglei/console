# 若依式 CRUD 布局参考（左树右表 / 树形表格）

> 来源：对 RuoYi-Vue-Plus「用户管理」「部门管理」两张截图的拆解，整理为可直接照做的规范。供 p0（列表页共享基础层）与 p1（organization 模块）的实现者参照，其他列表页按 §8.1 取用。

## 0. 适用范围与结论

- 适用：platform 资源列表页（build / organization），尤其 people（左树右表）与 departments（树形表格）。
- 不适用：chat 工作台、登录注册、profile / settings 这类非列表页。
- 一句话结论：这是「左侧一个范围选择器 + 右侧一条 查询 → 结果 → 翻页 的纵向流水线」。同一份部门数据在用户页是**筛选范围**（左树），在部门页是**被管理对象**（树表），形态因此完全不同；照抄时最容易抄错的就是把用户页那套勾选 + 批量 + 分页原样搬到部门页。
- 三个必须守住的 CSS 事实：整页固定高不滚动、左树与右表各自内部滚动、分页固定在卡片底部永远可见。做成整页滚动，分页会被顶到首屏之外，这是很多人照着抄却抄丢的一点。

## 1. 左树右表：结构骨架

```
Page  高度 = 100vh - 顶栏，flex-row，gap 20px，padding 20px（整页不滚动）
├── Aside 「部门结构」 card   宽 ~320px 固定，flex-shrink:0，高度撑满，flex-col
│   ├── 头部：标题 + 「‹」折叠按钮（收起后右侧表格拿到全宽）
│   ├── 搜索框：本地过滤树节点，不发请求
│   └── 树：flex:1，overflow:auto（树自己滚，不带动页面）
└── Main  flex:1，min-width:0（关键，否则表格把页面撑宽），flex-col，gap 20px
    ├── Filter 「筛选条件」 card   高度 auto，可折叠（「^」）
    │   └── 表单栅格：3 列 × (标签 ~80px 右对齐 + 控件 ~230px 固定宽)
    │       最后一行末尾空格放 [搜索][重置]，靠右
    └── List 「用户列表」 card   flex:1，min-height:0，flex-col
        ├── 头部：左 = 标题 + 一句说明 ｜ 右 = 工具栏
        │       [+新增 主色实心] [修改][删除][解锁 描边 + 语义色，未勾选置灰] [更多▾] │ [刷新][列设置]
        ├── 表格：flex:1，overflow:auto，表头 sticky
        │       列：☐ ｜ 用户名称(链接) ｜ 昵称 ｜ 部门 ｜ 手机 ｜ 状态(开关) ｜ 创建时间(两行) ｜ 操作(图标)
        └── 分页：flex-shrink:0，靠右
                共 N 条 ｜ [10条/页▾] ｜ ‹ 1 › ｜ 前往 [ ] 页
```

尺寸参考（1700px 宽截图）：左栏约 330px（≈19%），间距 20px，筛选卡约 145px 高，表格行高约 63px（时间两行时）。无左树的页面（build 模块）直接去掉 Aside，Main 独占一列，其余不变。

## 2. 各区域设计逻辑

### 2.1 左侧树 = 范围（scope），不是普通筛选
- 部门是层级数据，下拉框选不动；「选一个部门 = 看它及其所有子部门的人」这种语义只有树能表达。
- 常驻左侧是因为用户在部门之间来回切换的频率远高于改其它条件——它是**导航**，不是条件。
- 顶部搜索框只做树内过滤（高亮 / 收缩节点），不触发列表请求。
- 头部折叠按钮把整栏收起，给表格全宽。

### 2.2 筛选区独立成卡、放在表格上方
- 「重查询」形态：5 个条件、含日期区间，塞进表格标题栏放不下。
- 独立成卡的收益是能**单独折叠**，熟练用户收起后表格多一屏。
- 标签右对齐 + 控件固定宽 → 跨行对齐成整齐栅格；[搜索][重置] 放最后一格右侧（眼动终点）。
- 退化规则：条件 ≤ 3 个时，改为表格标题栏里的一行工具条（轻形态），不必用整卡。

### 2.3 列表卡头部 = 标题 + 一句说明 + 三层工具栏
- 说明文案示例：「共 9 条记录，支持部门筛选、状态切换、导入导出和角色分配。」——一句话说明这个页面管什么。
- 工具栏三层：① 主操作（新增，唯一实心）；② 依赖选中的批量操作（修改 / 删除 / 解锁，未勾选就置灰）；③ 低频操作收进「更多」（导入 / 导出 / 分配角色）。
- 最右两个图标按钮（刷新、列显隐）是「表格自己的设置」，用竖线与业务操作隔开。

### 2.4 表格细节
- 主键列（用户名）做成链接 = 详情入口。
- 状态列直接用开关：高频、可逆、后果轻的操作就地完成，不进编辑页。
- 创建时间拆两行：牺牲行高换列宽，日期时间对齐可扫。
- 操作列若干图标：编辑 / 删除 / 重置密码 / 分配角色，行级与批量是同一批动作的两种粒度。
- admin 行没有操作按钮：**权限可见性落到行级**——不可操作的对象按钮直接不渲染，而不是点了报错。

### 2.5 分页在卡片内部底部
- 总数、每页条数、页码、跳转四件套齐全。
- 放在卡片内而非页面底部：分页属于「这张表」，折叠筛选区时它要跟着表走。

## 3. 交互与状态模型

整页只有**一个查询对象**驱动一切：

```ts
query = { deptId, userName, nickName, phone, status, dateRange, pageNum, pageSize }
```

三个输入源都往这个对象里写，写完就重新拉列表：
- 点树节点 → `deptId` 变、`pageNum` 归 1。
- 点搜索 → 表单值写入、`pageNum` 归 1；点重置 → 清表单**也清树选中**（否则用户以为重置了，结果仍被部门限制着）。
- 换页 / 换每页条数 → 只改分页字段。

第二个独立状态是**选中集合** `selectedIds`，只影响工具栏：
- 行内操作和批量操作是同一批动作的两种粒度：批量走勾选，单条走行尾图标。
- 置灰必须说明原因（tooltip），规则如下：

| 按钮 | 启用条件 | 置灰时提示 |
|---|---|---|
| 新增 | 始终 | — |
| 修改 | `selectedIds.length === 1` | 请先勾选且仅勾选一行 |
| 删除 / 启用 / 停用 / 解锁 | `selectedIds.length >= 1` | 请先勾选至少一行 |
| 更多 › 导出 | 始终（按当前筛选导出） | — |

状态开关的标准流程：先弹确认（「确认要停用 xxx 吗？」）再改，因为旁边就是删除，误触成本不低；改完只刷新这一行，不整表重拉；失败回滚开关并 toast 原因。

`query` 对象正是 `useListUrlState` 应该接管的东西：树选中的 `deptId` 也进 URL，「分享某部门的人员列表」的链接才成立；`selectedIds` 不进 URL。

## 4. 树形表格变体（部门管理）

同一份部门数据的第二种呈现：部门在这里是**被管理的对象本身**，要看每个节点的属性（编码、排序、状态、时间）并对节点操作，树 + 表合体是唯一合理形态。

- **筛选区**：只有 3 个条件，一行放完，[搜索][重置] 直接放同一行末尾。树表按名称搜索有特殊语义：若依是后端返回扁平命中、前端 `handleTree` 组树，父子链断了就退化成平铺；更好的做法是**命中节点 + 祖先链一起返回 / 保留**，保持层级可读。
- **列表头部**：标题 + 一句说明；工具栏只有 [新增] [展开 / 折叠] [刷新]。**没有勾选列，没有批量修改 / 删除**——树结构下「批量删」的依赖关系太复杂（删父是否连子？），干脆不给。「展开 / 折叠」是树表专属的全局开关。工具栏形态由数据结构决定，不是模板。
- **六列讲究**：
  - 部门名称：层级靠缩进（每级约 16px）+ 展开箭头，只有有子节点的行才画箭头。
  - 类别编码：全空——这是新加的字段未回填，仍占一整列是小瑕疵；本项目没有对应字段就不要留空列。
  - 排序：`orderNum` 是**同级内**权重，不是全局序号，列里出现重复数字是正常的。
  - 状态：徽章「正常」，**不是开关**。停用一个部门会级联影响子部门和部门下用户，后果重 → 进编辑表单改。与用户页的开关形成「按后果分级」的对照：后果轻 → 开关就地改；后果重 → 进表单。
  - 创建时间：列宽够就单行，不像用户页拆两行。
  - 操作：编辑 / **新增子部门（+）** / 删除。「+」是树表的灵魂动作：在当前节点下新建，打开表单时 `parentId` 预填为当前行。若依默认根节点（`parentId = 0`）不显示删除；删除时后端拦「存在下级部门不允许删除」「部门存在用户不允许删除」并把原因原样返回前端——这就是「删除依赖拦截应为程序判断而非静态文案」的正确样子。
- **没有分页**：部门量级通常几十到几百，且分页会把父子拆到两页，所以树表一律全量加载，列表卡到表格底部直接结束。用户页分页是因为用户可能上万；两页在「要不要分页」上做出相反选择，都对。部门到几千级时，正确做法是**懒加载子节点**（点开箭头再拉），不是分页。

## 5. 外壳导航（侧栏 / 顶栏 / 页签）及取舍

- **侧栏（~210px）管「去哪」**：一级模块 + 二级菜单，分组可折叠，当前项高亮带描边；顶栏汉堡把整栏收成图标条。若依的核心机制：菜单不是代码写死的，是 `sys_menu` 表按角色下发——**菜单 = 路由 = 权限**三位一体，所以测试菜单也能直接挂进生产导航。
- **顶栏管「在哪 + 全局工具」**：面包屑与侧栏路径一致，目录级（如「系统管理」）不可点；右侧一排与业务无关的全局工具（搜索 ⌘K、消息、帮助、全屏、语言、字号、用户 + 工作区切换）。
- **标签页栏（tag-view）管「回到刚才」**：每打开一个菜单加一个页签，可关闭、首页固定无 ×、当前页签主色填充，右端有「刷新当前页」和批量关闭。本质是 `keep-alive` 的可视化，解决运营人员在多个列表间反复横跳时状态不丢的问题。代价：占一行高度、与浏览器标签语义重复、页签堆积。**本项目不照搬**：聊天工作台形态的产品用侧栏 + 面包屑即可，「回到刚才」由 URL 即状态承担。
- 截图可见的外壳瑕疵：长菜单名「物资设备态势监…」被截断且无 tooltip；`测试菜单1` / `ww` / `test` 直接挂进导航，说明菜单未按环境过滤。

## 6. 用户页 vs 部门页对照表

| | 用户管理 | 部门管理 |
|---|---|---|
| 部门数据的角色 | 筛选范围（左侧树） | 被管理对象（树形表格） |
| 页面骨架 | 左树右表 | 单列：筛选 + 树表 |
| 多选 / 批量 | 有 | 无 |
| 状态列 | 开关，就地切换 | 徽章，进表单改 |
| 分页 | 有 | 无，配「展开 / 折叠」 |
| 行操作 | 编辑 / 删除 / 重置密码 / 分配角色 | 编辑 / 新增子级 / 删除 |
| 专属工具 | 列设置、更多（导入导出） | 展开 / 折叠 |

同一份数据，两页共享的只有「部门树」这个数据源；呈现、工具栏、操作、分页全部不同。

## 7. 对照理想 CRUD 清单：做到的与缺的

**做到的**：范围树 + 重筛选分离；筛选可折叠；依赖选中的工具栏；多选列；批量 + 行级双粒度；就地状态切换；刷新与列设置；分页四件套；行级权限隐藏；页头说明文案；树表的新增子级 / 展开折叠 / 不分页；状态按后果分级（开关 vs 徽章）；删除拦截由后端程序判断并回传原因。

**没做到或看不出（本项目落地时必须补上）**：
- 操作列纯图标无文字 → 必须配 `UTooltip`，「+」尤其难猜是「新增子部门」。
- 修改 / 删除置灰不说为什么 → 加「请先勾选一行」提示（见 §3 表）。
- 时间是绝对时间 → 相对时间 + hover 完整值。
- 操作列没固定在右侧 → 列一多横向滚动时它会消失，需右侧 pin。
- URL 不同步查询条件（若依默认不同步，刷新即丢）→ `useListUrlState`。
- 空状态、加载骨架屏截图看不出 → 三态空状态（从未创建 / 筛选无结果 / 加载失败）+ `#loading` 骨架。
- 面包屑「系统管理」与页签栏信息重复；状态徽章只有一种颜色时看不出是否区分了「停用」；树表搜索后层级会断。

## 8. 映射到本项目

### 8.1 页面级建议
- organization 模块：把「部门树」做成 **people 页的左侧范围树**（按部门看人是最高频动作），departments 页改成**树形表格**；部门本身的增删改仍走独立页。
- build 模块（agents / workflows / plans）：套用「筛选卡 + 列表卡 + 分页」三段式，无左树；条件 ≤ 3 个的列表按 §2.2 退化为标题栏工具条。
- `departments/create/index.vue:18` 已支持 `?parent=`，「新增子部门」只差在行操作里加一个按钮跳 `create?parent=<id>`。

### 8.2 Nuxt UI 4.10 组件对应表（均已在 node_modules 确认存在）

| 截图区域 | 本项目对应 | 组件 |
|---|---|---|
| 左侧部门树 + 本地搜索 | `stores/departments` 层级数据 | `UTree` + `UInput`（本地过滤） |
| 筛选卡（可折叠） | manager hook 的 filters | `UCollapsible` + `UInput` / `USelect` / `UInputDate` |
| 工具栏（主操作 / 批量 / 更多） | 现在只有页头一个「新建」 | `UButton` + `UDropdownMenu`（`build-resource-table` 已有此模式） |

### 8.3 三个 CSS 坑
1. 外层容器 `h-[calc(100vh-顶栏高度)]`，否则整页滚动、分页被顶出首屏。
2. 右侧主列 `min-w-0`，否则表格把页面撑宽出现横向滚动。
3. 列表卡 `min-h-0` + 表格容器 `overflow:auto`，否则表格撑高页面而不是内部滚动。

### 8.4 窄屏策略
- `< 1200px`：左树收成抽屉（`USlideover`）或退化为筛选区里的一个部门级联选择；筛选卡栅格降为 2 列 / 1 列。
- 树表在窄屏保留缩进与箭头，隐藏次要列（排序、时间），操作列仍右侧固定。

### 8.5 树表与人员页的联动约定
- people 页树选中的 `departmentId` 进 URL；departments 页「查看成员」可跳 `people?departmentId=<id>`，复用同一 `query` 契约。
- 部门增删改或状态变更后，people 页左树需重新拉取（或共用 store 缓存失效），避免树与表不一致。
